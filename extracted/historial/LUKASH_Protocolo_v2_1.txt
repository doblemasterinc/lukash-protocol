|                                                                       |

2. MOTOR A — MECÁNICA DEFINITIVA DE ABSORCIÓN

La ambigüedad del diseño original sobre el origen de los $LUKA que se
'absorbían y quemaban' quedó resuelta con un mecanismo más potente:
compra en mercado abierto seguida de quema inmediata. Dos impactos
positivos encadenados por fee.

2.1 El Mecanismo Unificado: Compra + Quema

+----------------------------------+-----------------------------------+
| Diseño v1.0 — Ambiguo            | Diseño v2.1 — Limpio y Superior   |
|                                  |                                   |
| El contrato 'absorbe $LUKA del   | El 35% del fee en SOL compra      |
| protocolo' para quemarlos. No se | $LUKA en mercado abierto vía      |
| especificaba de dónde venían     | Jupiter SDK. Los $LUKA adquiridos |
| esos $LUKA. Circularidad         | se envían directamente a          |
| contable no resuelta.            | dirección null.                   |
|                                  |                                   |
| - ¿Del LP inicial? → el mismo LP | - Sin circularidad: los $LUKA     |
|   que se quería proteger         |   vienen del mercado              |
|                                  |                                   |
| - ¿De reservas internas? → no    | - Presión de compra real y        |
|   estaban contabilizadas         |   visible on-chain                |
|                                  |                                   |
| - ¿Del mercado? → no estaba      | - Quema inmediata: deflación      |
|   especificado                   |   confirmada en la misma tx       |
|                                  |                                   |
| Resultado: mecanismo             | - El LP no se toca: crece por     |
| técnicamente incompleto.         |   separado con el capital inicial |
|                                  |                                   |
|                                  | Resultado: dos impactos positivos |
|                                  | por cada fee de Motor A.          |
+----------------------------------+-----------------------------------+

| NOTA SOBRE EL LP DEL PROTOCOLO:                                       |
|                                                                       |
| El 30% del capital inicial destinado al LP (en Meteora) es            |
| independiente del Motor A.                                            |
|                                                                       |
| No se usa como fuente de $LUKA para quemar. Crece con la apreciación  |
| de activos y con los fees                                             |
|                                                                       |
| que el propio pool genera por volumen de trading. El Motor A alimenta |
| el LP solo de forma indirecta:                                        |
|                                                                       |
| al reducir el supply y generar presión de compra, aumenta el precio,  |
| lo que mejora el valor del LP.                                        |
|                                                                       |
| Esta separación elimina la circularidad del diseño v1.0               |
| definitivamente.                                                      |

3. THROTTLE DINÁMICO DE QUEMA (P5)

Mecanismo anti-espiral que protege la Reserva Operativa en mercados
bajistas modulando la tasa de compensación del Motor B2 según el precio
relativo de $LUKA. Las quemas diferidas se acumulan en cola on-chain y
se ejecutan cuando el mercado se normaliza — nunca se cancelan.

  vs EMA30)                      B2            VAULT          
  ---------------- ------------- ------------- -------------- -------------
  P_m > 1.2 ×      ACELERADO     125% quema    100% desde     No aplica
  EMA30                          base          R_op           

  0.8 × EMA30 ≤    NORMAL        100% quema    100% desde     No aplica
  P_m ≤ 1.2 ×                    base          R_op           
  EMA30                                                       

  0.5 × EMA30 ≤    CONSERVADOR   60% quema     60% desde R_op 40% diferido
  P_m < 0.8 ×                    base          inmediata      en cola
  EMA30                                                       

  P_m < 0.5 ×      DEFENSIVO     25% quema     Solo quema     75% diferido
  EMA30                          base          directa activa en cola
  -------------------------------------------------------------------------

+-----------------------------------------------------------------------+
| EMA30 = Precio Promedio Móvil Exponencial de 30 días de $LUKA,        |
| calculado por LUKAI vía Pyth Network.                                 |
|                                                                       |
| La cola de diferidos es pública on-chain. Los usuarios pueden ver     |
| cuántas quemas están pendientes.                                      |
|                                                                       |
| Cuando el precio regresa a zona NORMAL, la cola se ejecuta            |
| progresivamente (max 10% de la cola por semana).                      |
|                                                                       |
| Las quemas diferidas crean un 'bono de deflación futuro' que          |
| incentiva la compra en bajistas.                                      |
|                                                                       |
| El Modo DEFENSIVO es el mecanismo de supervivencia del protocolo.     |
| Preserva R_op para el largo plazo.                                    |

5. PROTECCIÓN DEL POOL DE LIQUIDEZ (P3)

El Jaguar Shield v1.0 protegía el Vault pero no el Pool de Liquidez.
Esta es la extensión que cierra esa vulnerabilidad crítica. Dos
mecanismos complementarios: incentivos proactivos y freno reactivo.

5.1 Sistema de LP Comprometido — Incentivos por Lock Voluntario

  ------------------------------------------------------------------------
  NIVEL            LOCK          REWARD BASE   REWARD        BENEFICIO
                   VOLUNTARIO                  ADICIONAL     EXTRA
  ---------------- ------------- ------------- ------------- -------------
  LP Básico        Sin lock      35% fee       —             Retiro
                                 estándar                    inmediato
                                                             siempre
                                                             disponible

  LP Comprometido  30 días       35% fee       +5% del pool  Badge
  30d              voluntario                  rewards       on-chain
                                                             'Jaguar Cub'

  LP Jaguar 90d    90 días       35% fee       +12% del pool NFT Badge
                   voluntario                  rewards       'Jaguar' +
                                                             voto en
                                                             parámetros

  LP Fundador 365d 365 días      35% fee       +20% del pool Gobernanza
                   voluntario                  rewards       premium +
                                                             yield
                                                             priority
  ------------------------------------------------------------------------

+-----------------------------------------------------------------------+
| FUENTE DE FINANCIAMIENTO DE LOS REWARDS ADICIONALES:                  |
|                                                                       |
| El reward adicional para LP Comprometido, Jaguar y Fundador no sale   |
| del pool existente de fees.                                           |
|                                                                       |
| Se financia con una reasignación del 3% del presupuesto de O&M        |
| mensual hacia el LP Reward Pool.                                      |
|                                                                       |
| Esto es sostenible porque un LP estable reduce el slippage del        |
| protocolo, lo que aumenta el volumen                                  |
|                                                                       |
| de trading y por ende los fees totales — el costo del incentivo se    |
| autofinancia con el tiempo.                                           |
